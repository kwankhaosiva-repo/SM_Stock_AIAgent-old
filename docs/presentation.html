บทที่ 1Chapter 1

ทำไมถึงเริ่มทำ — ปัญหาของบอทหุ้นทั่วไปWhy we started — the fatal flaws of naive stock bots

เรื่องมันเริ่มจากคำถามง่ายๆ: "เราจะมี AI ดูหุ้นส่วนตัวบน LINE ที่บอกได้เสมอว่าแต่ละคำแนะนำอ้างอิงจากหลักฐานอะไร โดยไม่ต้องเสียค่าบริการรายเดือนแพงๆ ได้ไหม?" It started with a simple question: "Can we build a personal stock assistant on LINE that always shows verified evidence behind every insight, without paying expensive monthly API bills?"

บอท AI แชทเรื่องหุ้นทั่วไปในท้องตลาดมี 3 ปัญหาอันตรายที่ผู้ใช้ไม่ค่อยรู้ตัว: Naive LLM stock chatbots suffer from three critical hazards:

  • AI คิดเลขและแต่งตัวเลขเอง (Hallucinated Math) — โมเดลภาษาชอบเดาราคา P/E, RSI หรือคำนวณแนวรับแนวต้านแบบมั่วซั่ว แต่พูดจาดูมั่นใจมาก ทำให้นักลงทุนตัดสินใจผิดพลาด Hallucinated financial metrics — LLMs confidently fabricate prices, P/E ratios, and RSI thresholds because language models cannot reliably calculate math.
  • พึ่งพา Provider เจ้าเดียว = เสี่ยงล่ม (Single Point of Failure) — วันดีคืนดี API เจ้าประจำโควตาเต็ม (429), เครดิตหมด (402), หรือถอดโมเดลออก (404) บอทจะหยุดตอบสนองทันที Single-provider fragile dependencies — Quota exhaustion (429), expired credits (402), or dropped model tags (404) immediately break the bot.
  • API หุ้นบล็อก Cloud IP & ข้อมูลไทยเข้าถึงยาก — Yahoo Finance และ Financial data providers มักบล็อก IP data center ฝั่ง Google Cloud/AWS ส่วนข้อมูล SET มี sandbox จำกัด Cloud IP rate-limiting & fragmented Thai market feeds — Yahoo Finance blocks Cloud IPs, while official Thai SET feeds require authenticated sandbox handshakes.
หัวใจการออกแบบของโปรเจกต์: ห้ามให้ AI คำนวณตัวเลขเด็ดขาด (Python คิดเลข 100% — AI มีหน้าที่แค่เรียบเรียงและตีความ) + ทุกเหตุผลต้องติด Tag แหล่งที่มา [จากข่าว] [จากงบ] [จากสถิติ] พร้อมระบบสำรอง Failover 8 เจ้าไม่มี downtime Core design principle: LLMs never do math (Python computes 100% — AI only interprets) + every claim carries verified evidence tags [From News] [From Financials] [From Indicators] with an 8-provider failover chain for zero downtime.
บทที่ 2Chapter 2

ปัญหาจริงที่เจอระหว่างทาง และวิธีแก้ในโค้ดProblems encountered — and how we engineered fixes

ระหว่างพัฒนาไม่ได้ราบรื่นเลย นี่คือ 6 อุปสรรคจริงที่เราเจอ พร้อมวิธีแก้ในโค้ดของโปรเจกต์: Building a production-ready assistant was not trivial. Here are 6 real roadblocks and their exact code-level solutions:

1
ปัญหาProblem

AI แต่งตัวเลขราคาและอินดิเคเตอร์AI fabricates prices and indicators

ถ้าสั่งให้ LLM วิเคราะห์ตรงๆ มันจะสร้างราคาปิดและคำนวณ RSI ผิดพลาดเกือบตลอดเวลา Asking an LLM directly leads to fabricated historical closes and flawed RSI/moving-average calculations.

แก้:Fix: Deterministic Pipeline: indicators.py (RSI-14, SMA-20/50, Volatility, 30-day Support/Resistance) + financial_ratios.py (D/E, ROE, Margin) ส่งตัวเลขสำเร็จรูปให้ AI ตีความเท่านั้น Deterministic pipeline: indicators.py & financial_ratios.py calculate all math in Python/pandas and pass read-only numbers into the LLM context.
2
ปัญหาProblem

Quota ฟรีหมด = บอทตอบไม่ได้Free-tier quotas expire = bot goes down

Gemini ติด 402/เครดิตหมด, Groq ติด 404 (model เลิกให้บริการ), Mistral ติด 429 Gemini hits billing 402, Groq throws 404 (model retired), or Mistral triggers rate-limit 429.

แก้:Fix: 8-Provider Failover Chain (Groq → Cerebras → Mistral → Cloudflare → OpenRouter → UnoRouter → Router9 → Ollama) ส่ง prompt เดิมต่อทันที + 404 Self-Healing ดึง /models จริงมาแคชตัวใหม่ 8-provider failover chain with context-forwarding failover + 404 self-healing that live-queries /models to rebind working model names automatically.
3
ปัญหาProblem

Cloud Run โดนบล็อก IP ดึงหุ้นไม่ได้Cloud Run IPs get rate-limited by data feeds

Yahoo Finance และเว็บข่าวในบางช่วงบล็อก Request ที่มาจาก Google Cloud data centers Yahoo Finance frequently blocks requests originating from public Google Cloud data center IP ranges.

แก้:Fix: Multi-Data Provider Fallback: Settrade Open API (หุ้นไทย) → Yahoo → FMP → Home Relay Agent ผ่าน Cloudflare Tunnel ดึงจากเน็ตบ้านส่งกลับขึ้น Cloud Run Multi-data provider fallback: Settrade Open API → Yahoo → FMP → local home relay agent tunneling market data via Cloudflare Tunnel.
4
ปัญหาProblem

ผู้ใช้กดปุ่มซ้ำยิง AI ซ้ำซ้อนDouble-tapping buttons triggers duplicated AI calls

LINE ผู้ใช้ชอบกดปุ่มย้ำๆ ทำให้เกิด Worker รันชนกัน เปลือง Quota และส่งการ์ดซ้ำ Users spam LINE buttons while waiting, spawning concurrent duplicate worker jobs and burning quota.

แก้:Fix: 30s Press Debounce Lock ใน Firestore (ต่อ user+symbol+action) + Shared Snapshot Cache 15 นาที + X-Line-Retry-Key Idempotency key 30s press-debounce locks in Firestore per user+action+symbol + 15-minute shared snapshot cache + UUID idempotency keys.
5
ปัญหาProblem

LINE Webhook หลุด Timeout 2 วินาทีLINE Webhooks drop connection at 2 seconds

การวิเคราะห์ 4 เอเจนต์ใช้เวลา 4-8 วินาที ถ้าตอบช้า Webhook ของ LINE จะตัดการเชื่อมต่อ Running 4 agents takes 4-8s; holding the HTTP webhook connection open causes LINE to timeout and retry.

แก้:Fix: Instant Acknowledgment: Webhook ตอบ HTTP 200 + ข้อความ "⏳ กำลังวิเคราะห์..." ทันที แล้วส่งงานเข้า Background Job Queue ก่อน Push ผลลัพธ์กลับ Instant acknowledgment: returns HTTP 200 + instant "⏳ Processing" status, handing execution off to background workers that push completed Flex cards.
6
ปัญหาProblem

ข่าวมีทั้งสแปมและหัวข้อซ้ำNews feeds contain noise and duplicated headlines

ดึงข่าวดิบมา 20 ชิ้น มีแต่ข่าวปั่นหุ้นและข่าวซ้ำสำนัก ทำให้ AI สรุปผลคลาดเคลื่อน Raw RSS/Finnhub feeds dump sponsored noise and multi-outlet duplicates that skew AI verdicts.

แก้:Fix: News Cleaning Pipeline (news_cleaning.py): ดึง 20-30 ข่าว → กรอง URL/หัวข้อซ้ำ → คัด Top 8 พร้อมบอกสถิติ raw=23 -> kept=8 อย่างโปร่งใส News cleaning pipeline: deduplicates by title similarity and source domain, ranking the top 8 impactful stories with transparent logging.
บทที่ 3Chapter 3

ทำไมต้องเป็น Evidence-Based ArchitectureWhy evidence-based architecture

ในโลกการเงิน "ความน่าเชื่อถือและแหล่งที่มา สำคัญกว่าความฉลาดของภาษา" In financial engineering, traceable evidence matters far more than persuasive prose.

บอท AI ปกติทั่วไปConventional AI Chatbots

ถามว่า "PTT น่าซื้อไหม" → LLM บรรยายยาวเหยียด แต่ไม่บอกว่าตัวเลขมาจากไหน และไม่รู้ว่าข่าวจริงหรือข่าวเก่าเมื่อ 2 ปีก่อนใน Memory Asks "Should I buy PTT?" → LLM returns long generic paragraphs, mixing up 2-year-old memory with hallucinated current PE ratios.

สถาปัตยกรรมของเราOur Evidence-Based Contract

แยกข้อมูลเป็น 3 เสาหลัก: [จากข่าว] (อ้างอิง URL ข่าวจริง) / [จากงบ] (D/E, Margin จากงบล่าสุด) / [จากสถิติ] (RSI, แนวรับต้านจากราคา 30 วัน) Separates insights into 3 strict pillars: [From News] (verifiable URLs), [From Financials] (audited ratios), and [From Indicators] (30-day technical ranges).

ด่านตรวจคุณภาพ (Reviewer Gate): เรามี Agent ตัวที่ 4 RiskEvidenceReviewer คอยตรวจทานคำตอบก่อนส่งถึงมือผู้ใช้ ถ้าพบคำการันตีผลตอบแทนเกินจริง ข้อมูลเก่าเกิน 15 นาที หรืออ้างอิงตัวเลขที่ไม่มีใน Context จะ Reject ให้แก้ทันที Quality Reviewer Gate: The 4th agent, RiskEvidenceReviewer, scrutinizes advice before delivery. Any guaranteed-return language, stale data (>15m), or ungrounded statistics gets flagged and sent back for revision.
บทที่ 4Chapter 4

ทำไมเลือกเครื่องมือเหล่านี้Why we selected these tools

ทุกชิ้นส่วนในระบบถูกคัดเลือกด้วยเหตุผลชัดเจน — ตารางนี้เปรียบเทียบกับตัวเลือกที่เรา "ไม่ใช้": Every framework in our repository was vetted against discarded alternatives:

เครื่องมือที่เลือกSelected Tool เหตุผลที่เลือกWhy We Chose It ตัวเลือกที่ไม่ใช้ & เหตุผลRejected Alternative & Why
LangGraph StateGraph ชัดเจน รองรับ Parallel Fan-out (รัน News + Fundamental พร้อมกัน) และทำ Reviewer Reflection loop ได้สมบูรณ์ Explicit StateGraph supporting parallel fan-out (News + Tech run concurrently) and cyclical reflection loops. LangChain Chains ยาวๆ — ควบคุม Flow แยกย่อยยาก และดีบัก State ข้ามเอเจนต์ลำบาก Linear LangChain Chains — hard to debug state branching and lacks clean cyclic review loops.
Failover Chain (8 Providers) รวม Free-tier โควตา (Groq, Cerebras, Mistral, Cloudflare, OpenRouter, UnoRouter...) สลับค่ายอัตโนมัติเมื่อ Error Aggregates free tiers across 8 providers with automatic fallback on quota exhaustion or dropped models. Single Paid API (OpenAI/Anthropic) — ค่าใช้จ่ายบานปลายเมื่อผู้ใช้แชทบ่อย และเสี่ยงล่มเมื่อตัดบัตรไม่ผ่าน Single Paid API — unpredictable API bills and complete downtime if subscription billing fails.
Flask + Gunicorn เบา รันเสถียร รองรับ Webhook และ Worker ใน container ขนาดกะทัดรัด Lightweight, stable, perfect for webhook ingestion with predictable gthread worker concurrency. Django — โครงสร้างหนักเกินไป มี ORM และ boilerplate มากเกินความจำเป็นสำหรับ Serverless Webhook Django — too heavy with redundant ORM boilerplate for a lightweight serverless webhook.
Google Firestore NoSQL Serverless สเกลเหลือ $0 ได้ ไม่ต้องดูแล connection pool และมี SDK Auth ผ่าน ADC ใน Cloud Run ทันที Serverless NoSQL that scales to zero ($0 idle cost), eliminating database connection pools and password secrets. Cloud SQL (PostgreSQL) — ต้องจ่ายค่าเปิดเครื่องทิ้งไว้ ~$15-30/เดือน แม้ไม่มีคนใช้งาน Cloud SQL (Postgres) — charges $15-30/month even when 100% idle.
Google Cloud Run Scale-to-zero (min-instances 0) + CPU Throttling คิดเงินเฉพาะช่วงมี Request ตอบโจทย์ $0/เดือน Scale-to-zero (min=0) + CPU throttling bills exclusively during active request execution for near-$0 operations. Compute Engine (VM) — ต้องเปิดเครื่อง 24/7 จ่ายค่าเช่าคงที่รายเดือน และต้องคอย Patch OS เอง Compute Engine (VM) — fixed hourly charges 24/7 plus ongoing OS patch maintenance overhead.
Pydantic v2 บังคับ Contract JSON ของ Agent ทุกตัว ถ้าโครงสร้างข้อมูลเพี้ยนระบบจะ fallback ทันที ไม่ปล่อย error หลุดไปหาผู้ใช้ Validates JSON contracts from LLMs; malformed outputs trigger deterministic fallbacks rather than crashing. Regex parsing — เปราะบาง พังง่ายเมื่อ LLM สลับตำแหน่งข้อความ Regex parsing — brittle and vulnerable to prompt phrasing shifts.

Workflow การวิเคราะห์หุ้นในระบบStock analysis execution workflow

กดเลือกหุ้น เช่น "PTT" → ระบบตรวจ Mutex Debounce Lock 30 วินาที เพื่อป้องกันการกดปุ่มซ้ำซ้อน Selects stock e.g. "PTT" → verifies 30-second mutex debounce lock to prevent duplicate taps.

2. ตรวจสอบ Shared Market Snapshot Cache2. Check shared market snapshot cache

ตรวจดูว่ามี Snapshot ที่ดึงไว้ใน 15 นาทีที่ผ่านมาหรือไม่ ถ้ามีใช้ร่วมกันได้ทันที ไม่ต้องดึงซ้ำ Checks if a shared snapshot was fetched in the last 15 minutes to save data requests.

3. Deterministic Extraction & Cleaning3. Deterministic extraction & cleaning

ดึงราคา งบการเงิน และข่าว 20-30 ข่าว → Python คำนวณ RSI/SMA/Support/Resistance และคลีนตัดข่าวขยะเหลือ Top 8 Fetches feeds → Python computes RSI/SMA/ratios and cleanses raw news to top 8 impactful stories.

4. Multi-Agent Analysis (ขนาน & ตรวจสอบ)4. Multi-agent execution & review
